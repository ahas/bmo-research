# bmo-research

プラットフォームのリサーチユニットです。調べる対象をカテゴリーごとのキューで管理するデーモンで、オーナーが登録した
ソース(Hugging Face Hub、arXiv、GitHub のリリース、フィード)から新しい対象を見つけ、それぞれを専用のリサーチランナーに
任せてカテゴリーの形式で調査させ、実行が保管したドキュメントの共有リンクをカテゴリーの受信者に知らせます。ランナー
(`docs/runner.md`)は、チャットエージェントが `research/run` で依頼するすべての調査と、描画サービスの `references`
実行にも、agency が提供するスロットとロールセッションの上で応えます。`it` はマニュアルか調査を依頼し、対象がラボの
カードのいずれかに合うというマニュアルが出ればオーナーの判断を仰ぎます。`security` はプラットフォームのスタックに
照らして判断したセキュリティ勧告を依頼し、スタックに関わる勧告であればパッチを当てるかを尋ねます。`economy` は
1 日分の項目を 1 本のブリーフにまとめ、その数値を保管します。デーモンが行うのは調査と通知までです。レポートが求める
作業は、オーナーの判断を受けてチャットエージェントが起票します。

設計は `docs/design.md`、ルートとツールとこのユニットが行う呼び出しは `docs/api.md`、設定は `docs/settings.md`、
テーブルは `docs/store.md`、ソースの種類は `docs/sources.md` にあります。

## 構成

| フォルダー | 内容 |
|---|---|
| `crates/` | Rust のワークスペース:`client`(境界の型と HTTP クライアント)と `server`(デーモン、ルート、ストア、スキャンとディープダイブ、そして `bmo-research` バイナリ) |
| `tools/` | ツールホストが `research` 名前空間の下に置くツール `research`:マニフェスト、スキーマ、実行ファイルのクレート |
| `prompts/` | 形式ごとに 1 つずつの韓国語の質問テンプレート、通知の文言、保管されたドキュメントを読むときの文言 |
| `docs/` | 設計、API とその OpenAPI ドキュメント、設定、ストア、ソース |
| `src/` | コードを持たない、リポジトリ自身のパッケージ |
| `tests/` | すべてのテスト:ストアとキューのルール、ソースのリーダー、スタンドインのサーバーを相手にしたスキャンとディープダイブ、ルート、リポジトリの検査 |
| `deploy/` | デプロイが再起動し監視するユーザーユニット |

ルートには Cargo のワークスペース、`rustfmt.toml`、言語台帳 `korean-ledger.json`、テストベッドの `testbed.toml`、
`CLAUDE.md`、そして MIT の `LICENSE` があります。
